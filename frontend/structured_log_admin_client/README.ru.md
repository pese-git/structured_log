# structured_log_admin_client

Самостоятельный admin-клиент для
[`structured_log_server`](../../backend/structured_log_server): вход, группы и
проекты с их секретными ключами, пользователи, просмотрщик логов, аудит.

Не публикуется — это приложение, а не библиотека.

## Состояние

Работает: вход (включая принудительную смену пароля при первом входе), группы,
проекты и их квоты, секретные ключи, команды и их состав, просмотрщик логов
с живой лентой, настройки аккаунта, экран аудита, управление пользователями
(создание, редактирование, блокировка/разблокировка, удаление) и выдача
ролей — раздел «Доступ» группы/проекта выдаёт роль пользователю или команде,
сужая список ролей до того, что разрешает токен вызывающего (подсказка, не
проверка — решает всё равно сервер); урезанная форма на экране пользователя
остаётся только для `admin`, по одному пользователю за раз.

Нет: самостоятельной регистрации, восстановления пароля и подтверждения
email. Пункт меню, открывающий пустой экран, хуже непредложенного — что
именно сделано, видно в
[tasks.md](../../openspec/changes/add-structured-log-server/tasks.md).

**Одно, что нужно знать до запуска против сервера на другом хосте: по
умолчанию так не получится.** CORS-заголовков сервер не шлёт, пока оператор
явно не включит их (`--cors-allowed-origins`, см. README самого сервера) —
без этого браузер отклоняет запрос, не отправив его. Клиент отдаётся рядом
с API за одним origin ([deploy/](../../deploy/)), а его бандл собирается с
пустым base URL — это остаётся эталонным способом развёртывания и там, где
CORS доступен.

### Языки

Английский и русский. Пока язык не выбран, приложение следует языку браузера
(для любого другого — английский); выбрать можно в **Настройки аккаунта →
Язык** (или переключателем English / Русский в углу экранов входа и
принудительной смены пароля), выбор хранится в `localStorage` браузера. Тексты лежат в
`lib/l10n/*.arb` и читаются через `context.l10n`; после правки ARB запустите
`flutter gen-l10n` (сгенерированные файлы коммитятся).

### Экран аудита

Административные действия и события аутентификации одной таблицей под одним
набором фильтров: разбирающий инцидент оператор задаёт один вопрос, и вход,
предшествовавший изменению, — часть ответа.

Пункт навигации появляется только у токена, чей claim `roles` несёт `admin` в
глобальной области. Claim читается без проверки подписи, и это законно ровно по
одной причине: он решает, что **предложить**, а не что разрешить. Сервер
переопределяет роли на каждом запросе и отвечает 403 независимо от токена, а
экран рисует это отказом. Подделанный токен покупает пункт меню и сообщение об
ошибке. Следствие стоит назвать: claim — снимок на момент выпуска токена,
поэтому отозванная в середине сессии роль оставит пункт до обновления.

Запись без инициатора называет, какого именно «никого»: попытка под
несуществующей учётной записью или сам сервер, — и запроса за именем не уходит,
потому что учётной записи нет. В теге действия стоит строка провода
(`project.quota_updated`) — то, по чему фильтруют и что документирует API;
человекочитаемое имя на текущем языке интерфейса — тултип.

## Архитектура

Послойно внутри каждой фичи — `domain` / `application` / `infrastructure` /
`presentation`, плюс `lib/shared/` для сквозного. Директории появляются вместе
с первым файлом, а не заводятся пустыми.

| Задача | Выбор | Где |
|---|---|---|
| UI-кит | `fluent_ui`, компонуется из `structured_log_admin_ui` | `lib/app/`, `presentation/` фич |
| HTTP | `dio` + `retrofit`; SSE вручную на том же инстансе | `lib/shared/api/` |
| Ожидаемые ошибки | `fpdart` `Either`, но не для программных ошибок | `lib/shared/api/api_failure.dart` |
| Модели | `freezed` + `json_serializable` | `lib/shared/api/dto/` |
| DI | `cherrypick` | `lib/shared/di/` |
| Состояние | `flutter_bloc` | `presentation/` фич |
| Токены | `flutter_secure_storage`, никогда не shared preferences | `lib/shared/auth/` |
| Диагностика | `structured_log` | `lib/shared/logging/` |

### Три инстанса Dio, а не один

Это стоит знать до того, как трогать `ApiClient`:

- основной несёт перехватчик аутентификации — подставляет access-токен и один
  раз обновляет его при 401;
- клиент обновления идёт без перехватчика: refresh, которому ответили 401 на
  основном инстансе, вошёл бы обратно в тот самый перехватчик, который его и
  запустил;
- клиент повтора переигрывает исходный запрос уже с новым токеном.

Токен-эндпоинт исключён не только по флагу, но и по пути: 401 от него означает
неверный пароль или израсходованный refresh-токен, и обновление в ответ на
любое из двух превращает неудачный вход в попытку продлить сессию.

Параллельные 401 делят одно обновление. Без этого каждый запрос тратил бы
refresh-токен, и на сервере, который их ротирует, все кроме первого предъявили
бы только что отозванный.

## Запуск

```bash
flutter run -d chrome --dart-define=STRUCTURED_LOG_BASE_URL=https://logs.example.com
```

Base URL — compile-time define, по умолчанию `http://localhost:8080`.

## Кодогенерация

`*.g.dart` и `*.freezed.dart` не коммитятся:

```bash
dart run build_runner build --delete-conflicting-outputs
```

или `dart run melos run generate` из корня репозитория. В CI шаг идёт до
`analyze`/`test`.
