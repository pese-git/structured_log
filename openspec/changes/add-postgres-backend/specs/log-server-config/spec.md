## MODIFIED Requirements

### Requirement: Набор обязательных параметров зависит от выполняемой команды
Проверка обязательности параметров SHALL выполняться применительно к запускаемой команде и к выбранному `db-backend`: для `create-admin` и для `serve` обязательны настройки подключения к *выбранному* backend'у хранения — путь к файлу базы данных при `db-backend=sqlite`, host/port/database/username PostgreSQL при `db-backend=postgres` — и не обязательны настройки другого backend'а, если он не выбран; для `create-admin` дополнительно отсутствие JWT-секрета или настроек SMTP SHALL не препятствовать её выполнению.

#### Scenario: create-admin выполняется без JWT-секрета и SMTP
- **WHEN** выполняется `create-admin` с указанным путём к базе данных (при `db-backend=sqlite`, по умолчанию), но без заданного JWT-секрета и без настроек SMTP
- **THEN** команда выполняется успешно и создаёт администратора

#### Scenario: create-admin с backend'ом Postgres не требует пути к SQLite
- **WHEN** выполняется `create-admin` с `--db-backend=postgres` и заданными настройками подключения к PostgreSQL, но без `--db-path`
- **THEN** команда выполняется успешно и создаёт администратора в указанной базе PostgreSQL — отсутствие `--db-path` не препятствует выполнению

## ADDED Requirements

### Requirement: Настройка выбора backend'а хранения
Сервер SHALL принимать параметр `db-backend` (`--db-backend` / `STRUCTURED_LOG_DB_BACKEND`), принимающий одно из значений `sqlite`/`postgres`, по умолчанию `sqlite`. Значение вне этого набора SHALL быть ошибкой конфигурации, обнаруживаемой в общей фазе проверки конфигурации до открытия порта.

#### Scenario: Недопустимое значение backend'а отклоняется при старте
- **WHEN** `--db-backend`/`STRUCTURED_LOG_DB_BACKEND` задан значением, отличным от `sqlite`/`postgres`
- **THEN** сервер отказывается стартовать с ошибкой конфигурации, называющей допустимые значения

### Requirement: Настройки подключения к PostgreSQL следуют существующему конвенту аргументов и секретов
Host/port/database/username подключения к PostgreSQL SHALL приниматься обычными аргументами командной строки/переменными окружения (видны в `--print-config`, не секреты). Пароль SHALL приниматься только как секрет — из переменной окружения или файла с суффиксом `_FILE` — тем же способом, что JWT-signing-секрет, пароль SMTP и пароль bootstrap-администратора; аргумента командной строки для пароля SHALL не существовать.

#### Scenario: Пароль PostgreSQL нельзя передать аргументом
- **WHEN** оператор передаёт аргумент командной строки, похожий на передачу пароля подключения к PostgreSQL
- **THEN** запуск отклоняется как неизвестный аргумент — такого флага в интерфейсе нет

#### Scenario: Несекретные настройки подключения видны в --print-config
- **WHEN** вызван `--print-config` при `--db-backend=postgres`
- **THEN** host/port/database/username подключения к PostgreSQL печатаются с их значением и источником, а пароль — как `***` с источником, тем же способом, что остальные секреты

### Requirement: Размер пула соединений и режим TLS для PostgreSQL — отдельные настраиваемые параметры
Сервер SHALL принимать отдельный от `db-read-pool-size` параметр размера пула соединений PostgreSQL и отдельный параметр режима TLS для этого подключения, оба — со значением по умолчанию, если не заданы явно; значение по умолчанию режима TLS SHALL не быть полным отключением шифрования.

#### Scenario: Размер пула PostgreSQL настраивается независимо от db-read-pool-size
- **WHEN** заданы одновременно `--db-backend=postgres`, размер пула соединений PostgreSQL и `--db-read-pool-size`
- **THEN** сервер использует заданный размер пула соединений PostgreSQL для подключений к базе, а `--db-read-pool-size` не влияет на поведение (`log-server-postgres-backend`)

#### Scenario: Режим TLS по умолчанию не отключает шифрование
- **WHEN** `--db-backend=postgres` задан без явного режима TLS
- **THEN** сервер использует режим TLS по умолчанию, отличный от значения, полностью отключающего шифрование соединения
