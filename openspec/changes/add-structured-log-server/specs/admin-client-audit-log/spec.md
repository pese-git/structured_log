## ADDED Requirements

### Requirement: Экран аудита доступен только администратору
Приложение SHALL предоставлять экран просмотра аудит-лога (`GET /v1/audit-log`), видимый и доступный только пользователю с ролью `admin`; для остальных пользователей пункт навигации к нему SHALL быть скрыт.

#### Scenario: Экран аудита скрыт для не-admin
- **WHEN** текущий пользователь не имеет `RoleAssignment(role: admin, scope: global)`
- **THEN** пункт навигации к аудит-логу не отображается

### Requirement: Фильтры экрана соответствуют параметрам API
Экран SHALL предоставлять элементы управления для каждого параметра фильтрации `GET /v1/audit-log` (`log-server-audit`): действие, тип цели, идентификатор цели, инициатор, диапазон времени — комбинируемые одновременно в одном запросе.

#### Scenario: Комбинация фильтров формирует один запрос
- **WHEN** администратор одновременно выбирает действие `project.blocked` и диапазон времени
- **THEN** приложение выполняет один `GET /v1/audit-log` запрос с обоими параметрами

### Requirement: Список результатов постранично подгружается курсором
Список записей аудита SHALL подгружаться постранично через курсор, возвращаемый `GET /v1/audit-log`, аналогично экрану логов (`admin-client-log-browser`); смена фильтров SHALL сбрасывать пагинацию к первой странице.

#### Scenario: Смена фильтра сбрасывает пагинацию
- **WHEN** администратор меняет фильтр после того, как уже подгружено несколько страниц результатов аудита
- **THEN** приложение выполняет новый запрос с первой страницы, а не продолжает пагинацию по старому курсору

### Requirement: Запись аудита показывает инициатора, действие, цель и детали
Экран SHALL отображать для каждой записи как минимум: инициатора (`actor_user_id`), действие (`action`), тип и идентификатор цели, время (`created_at`) и содержимое `metadata` в читаемом виде.

#### Scenario: Детали действия видны без обращения к сырому JSON вручную
- **WHEN** администратор открывает запись аудита с непустым `metadata`
- **THEN** приложение показывает содержимое `metadata` в структурированном, читаемом виде (например, список пар ключ-значение), а не просто сырую JSON-строку без форматирования
