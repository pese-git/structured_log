## ADDED Requirements

### Requirement: Конфигурация читается из аргументов командной строки и переменных окружения
Сервер SHALL принимать настройки при запуске из трёх источников с фиксированным приоритетом: аргумент командной строки имеет приоритет над переменной окружения, переменная окружения — над значением по умолчанию. Конфигурация SHALL читаться один раз при старте и SHALL не изменяться в течение жизни процесса.

#### Scenario: Аргумент командной строки переопределяет переменную окружения
- **WHEN** задана переменная окружения с портом и одновременно передан аргумент командной строки с другим портом
- **THEN** сервер слушает порт из аргумента командной строки

#### Scenario: Переменная окружения переопределяет значение по умолчанию
- **WHEN** задана переменная окружения для параметра, у которого есть значение по умолчанию, и соответствующий аргумент не передан
- **THEN** используется значение из переменной окружения

#### Scenario: Незаданный параметр принимает значение по умолчанию
- **WHEN** параметр не задан ни аргументом, ни переменной окружения, и у него есть значение по умолчанию
- **THEN** используется значение по умолчанию

#### Scenario: Пустая строка в переменной окружения равносильна её отсутствию
- **WHEN** переменная окружения задана пустой строкой
- **THEN** параметр считается незаданным и принимает значение по умолчанию, а не пустое значение

### Requirement: Имя аргумента и имя переменной окружения соответствуют друг другу механически
Каждому параметру конфигурации SHALL соответствовать аргумент в kebab-case и переменная окружения из тех же слов в SCREAMING_SNAKE_CASE с префиксом `STRUCTURED_LOG_` (например, `--http-port` и `STRUCTURED_LOG_HTTP_PORT`). Исключений из этого соответствия SHALL не быть, кроме параметров-секретов, у которых аргумента не существует.

#### Scenario: Каждому несекретному параметру соответствуют обе формы
- **WHEN** параметр конфигурации не является секретом
- **THEN** он может быть задан и аргументом командной строки, и переменной окружения, имена которых выводятся друг из друга по общему правилу

### Requirement: Секреты не принимаются в аргументах командной строки
Секретные значения (JWT-signing-секрет, пароль SMTP) SHALL приниматься только из переменной окружения или из файла, путь к которому задан переменной с суффиксом `_FILE`. Аргумента командной строки для секрета SHALL не существовать. Если для одного секрета заданы обе формы одновременно, сервер SHALL отклонить запуск как ошибку конфигурации.

#### Scenario: Флага для секрета не существует
- **WHEN** оператор передаёт аргумент командной строки, похожий на передачу JWT-секрета
- **THEN** запуск отклоняется как неизвестный аргумент — такого флага в интерфейсе нет

#### Scenario: Секрет читается из файла
- **WHEN** задана переменная с суффиксом `_FILE`, указывающая на существующий файл с секретом
- **THEN** сервер использует содержимое этого файла, отбросив завершающий перевод строки

#### Scenario: Одновременное задание значения и пути к файлу отклоняется
- **WHEN** для одного и того же секрета заданы и переменная со значением, и переменная с суффиксом `_FILE`
- **THEN** сервер отклоняет запуск с сообщением о конфликте, не выбирая одну из форм молча

#### Scenario: Недоступный файл секрета отклоняется
- **WHEN** переменная с суффиксом `_FILE` указывает на несуществующий или нечитаемый файл
- **THEN** сервер отклоняет запуск с сообщением, называющим путь

### Requirement: JWT-секрет обязателен и не генерируется автоматически
Сервер SHALL отказываться запускаться, если JWT-signing-секрет не задан ни одной из допустимых форм, и SHALL не генерировать его самостоятельно.

#### Scenario: Запуск без секрета отклоняется
- **WHEN** сервер запускается без заданного JWT-секрета
- **THEN** запуск отклоняется с сообщением о том, что секрет обязателен, и сервер не начинает слушать порт

#### Scenario: Рестарт не инвалидирует выданные токены
- **WHEN** сервер перезапускается с тем же заданным секретом
- **THEN** ранее выданные access-токены остаются валидными — секрет не меняется от перезапуска

### Requirement: Конфигурация проверяется целиком до открытия порта
Сервер SHALL проверять все значения конфигурации до того, как откроет порт и создаст файл базы данных. При обнаружении ошибок SHALL сообщать обо **всех** найденных проблемах сразу и завершаться с кодом выхода `78`, отличным от кода завершения при ошибке во время работы.

#### Scenario: Несколько ошибок сообщаются за один запуск
- **WHEN** одновременно заданы недопустимый порт и отрицательный срок хранения
- **THEN** сервер печатает обе ошибки за один запуск и завершается с кодом `78`

#### Scenario: Порт не открывается при плохой конфигурации
- **WHEN** конфигурация содержит ошибку
- **THEN** сервер не принимает ни одного соединения и не создаёт файл базы данных

#### Scenario: Нечисловое значение числового параметра отклоняется
- **WHEN** числовому параметру передано значение, не являющееся целым числом
- **THEN** запуск отклоняется как ошибка конфигурации

#### Scenario: Нераспознанное булево значение отклоняется
- **WHEN** булеву параметру в переменной окружения передано значение вне набора `true`/`false`/`1`/`0`/`yes`/`no` (без учёта регистра)
- **THEN** запуск отклоняется, а значение не трактуется как `false`

### Requirement: Неизвестный аргумент отклоняется, неизвестная переменная с префиксом предупреждает
Сервер SHALL отклонять запуск при неизвестном аргументе командной строки. При обнаружении переменной окружения с префиксом `STRUCTURED_LOG_`, не соответствующей ни одному параметру, сервер SHALL записать предупреждение и продолжить запуск.

#### Scenario: Опечатка в аргументе останавливает запуск
- **WHEN** передан аргумент, которого нет в наборе параметров
- **THEN** запуск отклоняется с указанием неизвестного аргумента

#### Scenario: Опечатка в переменной окружения не останавливает запуск, но заметна
- **WHEN** задана переменная с префиксом `STRUCTURED_LOG_`, не соответствующая ни одному параметру
- **THEN** сервер записывает предупреждение с именем этой переменной и продолжает запуск

### Requirement: Набор обязательных параметров зависит от выполняемой команды
Проверка обязательности параметров SHALL выполняться применительно к запускаемой команде: для `create-admin` обязателен только путь к базе данных, и отсутствие JWT-секрета или настроек SMTP SHALL не препятствовать её выполнению.

#### Scenario: create-admin выполняется без JWT-секрета и SMTP
- **WHEN** выполняется `create-admin` с указанным путём к базе данных, но без заданного JWT-секрета и без настроек SMTP
- **THEN** команда выполняется успешно и создаёт администратора

### Requirement: Эффективная конфигурация доступна для просмотра без секретов
Сервер SHALL предоставлять режим вывода эффективной конфигурации, показывающий для каждого параметра его значение и источник (аргумент, переменная окружения или значение по умолчанию), и завершающийся без запуска сервера. Значения секретов SHALL не выводиться ни в каком виде — вместо значения SHALL выводиться маскированный placeholder и источник.

#### Scenario: Источник каждого значения виден
- **WHEN** часть параметров задана аргументами, часть — переменными окружения, остальные не заданы
- **THEN** вывод показывает для каждого параметра, откуда взято его значение

#### Scenario: Секрет не раскрывается при выводе конфигурации
- **WHEN** JWT-секрет задан и выполняется вывод эффективной конфигурации
- **THEN** вместо значения секрета выводится маскированный placeholder, по которому видно только, что секрет задан и из какого источника

#### Scenario: Вывод конфигурации не запускает сервер
- **WHEN** выполняется вывод эффективной конфигурации
- **THEN** сервер завершает работу с кодом 0, не открывая порт

### Requirement: Справка по параметрам порождается из их описаний
Сервер SHALL предоставлять вывод справки, порождённый из тех же описаний параметров, что используются при разборе, — так, чтобы справка не могла разойтись с фактическим набором параметров.

#### Scenario: Справка содержит каждый параметр
- **WHEN** запрошена справка
- **THEN** в выводе присутствует каждый параметр конфигурации со своим описанием, и сервер завершается с кодом 0, не открывая порт
