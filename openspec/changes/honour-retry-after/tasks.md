## 1. Момент доезжает до кода отправки

- [x] 1.1 `BatchResult.retryAfter` — необязательное поле, заполняемое только `BatchResult.retryable`. `null` означает «ничего не сказано», а не «нуль».
- [x] 1.2 `_retryAfterOf`: разбор заголовка в обеих формах (секунды, HTTP-дата). Отсутствующий, нечитаемый, нулевой и прошедший — `null`, то есть backoff остаётся.
- [x] 1.3 Заполнение на всех восстановимых ответах транспорта: 5xx, `408`, `429`.

## 2. Пауза держит насос

- [x] 2.1 `_quietUntil` + `_passQuietPeriod()`: проверка перед **каждой** попыткой **каждого** батча, а не только перед повтором отклонённого.
- [x] 2.2 Ожидание — отменяемый `Timer` и `Completer`, не `Future.delayed`: последний держит изолят живым и не будится.
- [x] 2.3 Backoff пропускается ровно тогда, когда момент назван, — иначе паузы складывались бы.
- [x] 2.4 Отметка ставится до проверки `attempt == maxAttempts`: момент принадлежит соединению и должен держать батчи позади даже тогда, когда у этого попыток не осталось.

## 3. Потолок доверия

- [x] 3.1 `maxRetryAfter`, по умолчанию 5 минут; срок больше обрезается, `Duration.zero` отключает соблюдение целиком.
- [x] 3.2 Обрезание сообщается один раз за эпизод — по образцу `_overflowAnnounced`, чтобы сервер, застрявший на длинном `Retry-After`, не забил консоль по батчу на сообщение.

## 3a. Значения параметров проверяются при создании

- [x] 3a.1 Отрицательные `batchTimeout`, `retryBackoff`, `maxRetryAfter` и `requestTimeout` меньше либо равный нулю — `ArgumentError`. Числовые параметры проверялись и раньше, длительности — нет.
- [x] 3a.2 Ноль остаётся допустимым там, где он что-то значит: `maxRetryAfter: Duration.zero` отключает соблюдение заголовка, нулевой `retryBackoff` — «повторять сразу». Отрицательное значение попадало в ту же ветку случайно — опечатка выключала ровно то, ради чего параметр задан, ничего не сказав.
- [x] 3a.3 Мутациями проверено, что «ноль допустим» — утверждение, а не совпадение: guard, расширенный до `<= Duration.zero`, роняет соответствующий тест.

## 4. Закрытие

- [x] 4.1 `close()` будит ожидающий насос; неотправленные записи считаются потерянными и сообщаются с указанием оставшегося срока.
- [x] 4.2 Пауза при этом не игнорируется: залп после пробуждения не уходит.

## 5. Тесты

- [x] 5.1 Названный момент вместо backoff; пауза, держащая следующий батч (`maxAttempts: 1` — так видно, что ждут не ради повтора); обрезание по потолку с сообщением; нулевой потолок; `close()` без зависания.
- [x] 5.2 Через реальный сокет: секунды, HTTP-дата, нечитаемый заголовок, нуль.
- [x] 5.3 Мутациями проверены четыре теста, зеленевшие до реализации: нулевой потолок, нечитаемый заголовок, нулевой заголовок, область действия паузы. Backoff в охранных тестах поднят до 80 мс — на 5 мс «backoff устоял» и «заголовок соблюдён как нулевая пауза» неразличимы.
