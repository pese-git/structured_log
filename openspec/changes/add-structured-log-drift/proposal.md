## Why

`drift` — основная библиотека локальной базы в Dart и Flutter. Медленный или упавший запрос к ней — частая причина подвисшего или пустого экрана, но в лог он не попадает. Встроенный в drift `logStatements: true` печатает каждый запрос через `print` вместе со значениями аргументов. Значит, секреты (хэши паролей, токены, личные данные) уходят в консоль, а сама запись без уровня и структуры, без длительности и без ошибки. Поэтому в продакшене его выключают, и запросы остаются невидимыми: ни во встроенном просмотрщике, ни на `structured_log_server`. С версии 2.14 у drift есть `QueryInterceptor` — шов, через который проходит каждый запрос. Пакет-перехватчик, пишущий запросы записями `structured_log`, подключается одной строкой.

## What Changes

- Новый пакет `emb/structured_log_drift/` со `StructuredLogDriftInterceptor`, наследником `QueryInterceptor` из `package:drift`. Подключается через `executor.interceptWith(...)` или `connection.interceptWith(...)` и пишет записи `structured_log` с `category: 'db'`:
  - `db_query` — каждый выполненный запрос: вид (`select`/`insert`/`update`/`delete`/`custom`), текст SQL, длительность, число строк результата или затронутых строк;
  - `db_batch` — пакет (`batch`): число операторов и длительность;
  - `db_query_failed` — упавший запрос или пакет: ошибка, тип ошибки, стек;
  - `db_transaction_committed` и `db_transaction_rolled_back` — завершение транзакции.
- Медленный запрос (не короче порога, по умолчанию 500 мс) пишется уровнем `warning` с полем `slow: true`. Остальные — уровнем `debug`.
- Значения аргументов по умолчанию **не пишутся**: включаются явно и тогда описываются с обрезкой, двоичные данные — размером.
- Настройка по образцу остальных адаптеров: уровень на каждый вид записи (`null` выключает), `filter`, порог медленного запроса, включение аргументов, имя логгера, категория, готовый `BoundLogger`.
- Перехватчик стоит в пути запроса. Сбой логирования не меняет результата запроса, а исключение самого запроса пробрасывается вызывающему без изменений.
- Регистрация в `melos.yaml`, CI-джоба `drift-interceptor` со вторым прогоном тестов на нижней границе констрейнта `drift` и порог покрытия в `tool/coverage_floors.json`.
- Документация: README пакета (EN и RU), раздел «Related packages»/«Связанные пакеты» в README остальных живых пакетов `emb/`, корневые README, `AGENTS.md`, `docs/guides/embedding-guide.md`/`.ru.md`, главная страница и оглавление пакетов сайта.
- Вне рамок:
  - запросы миграций — drift выполняет их до перехватчика (см. design);
  - начало транзакции отдельной записью;
  - перевод `structured_log_server` на перехватчик (отдельной заявкой);
  - публикация на pub.dev (делается отдельно через `melos version`/`melos publish`).

## Capabilities

### New Capabilities
- `drift-query-logging`: `QueryInterceptor`, превращающий запросы, пакеты, ошибки и завершение транзакций drift в записи `structured_log` с длительностью, отметкой медленных запросов и аргументами, выключенными по умолчанию, без влияния на результат запроса.

### Modified Capabilities
(нет)

## Impact

- Новый пакет `emb/structured_log_drift/` (`publish_to` не задан, версия `0.1.0-dev.0`). Зависимости: `drift` (от 2.14.0, где появился `QueryInterceptor`) и `structured_log: ^0.3.0`. Пакет чистый Dart: тестируется `dart test` на `NativeDatabase.memory()` и работает с любым исполнителем drift, включая web.
- Меняются `melos.yaml`, `.github/workflows/ci.yml` (новая джоба) и `tool/coverage_floors.json`.
- В README остальных живых пакетов `emb/` появляется строка о новом пакете в разделе «Related packages». Код остальных пакетов не меняется.
