## Context

Подписи трёх скинов зашиты английскими литералами и **не совпадают между скинами** — каждый скин подбирал
формулировки под свою дизайн-систему:

| Подпись | Material | Fluent | Cupertino |
|---|---|---|---|
| поиск (подсказка) | `Search events, categories…` | `Search` | `Search events, categories…` |
| пауза / продолжение | `Pause` / `Resume` (тултип) | `Pause` / `Resume` (тултип) | иконка без текста и без семантической подписи |
| очистка | `Clear all` (тултип) | `Clear all` (тултип) | иконка без текста и без семантической подписи |
| все уровни | `All` | `All levels` | `All` |
| уровни фильтра | `Debug+` … `Error+` | `Debug and above` … | `Debug+` … `Error+` |
| все категории | `All` (`allLabel`) | `All types` (`allLabel`) | `All` (`allLabel`) |
| заголовок страницы | `Logs` | `Logs` | `Logs` |
| пусто / нет по фильтру | `No logs yet` / `No logs match the current filter` + абзацы | `No logs yet` / `No results found` + абзацы | как Material |
| сброс фильтров | `Clear filters` | `Clear filters` | `Clear filters` |
| заголовок контекста в деталях | `CONTEXT` | `CONTEXT` | `CONTEXT` |
| копирование | `Copy context` | `Copy` | `Copy` |
| закрыть шторку | `Close` | — | — |
| назад к списку | — | `Back to list` (тултип) | — (кнопку «назад» рисует `CupertinoNavigationBar`) |

Копирование во всех трёх — `Clipboard.setData` из `_copyContext`, `Future` уходит в `onPressed` без `await`:
об успехе никто не узнаёт, а ошибка (на web буфер обмена бывает недоступен) становится необработанной.

Потребитель, который это вскрыл, — Electro (`Electro/electro_workspace#188`): русский экран логов на
`structured_log_material` и снэкбар «Контекст скопирован».

## Goals / Non-Goals

**Goals:**

- Приложение задаёт любую подпись любого скина одним объектом, общим для трёх скинов.
- Без нового параметра тексты остаются ровно прежними, в том числе различия между скинами.
- Приложение узнаёт об успешном копировании и само решает, как это показать.
- Приложение, которому достаточно готового русского, получает его одной строкой в `localizationsDelegates`,
  без своих ARB (решение пользователя 19.10.2026, по ходу реализации).

**Non-Goals:**

- Зависимость от `flutter_localizations`/`intl` и `gen-l10n` в пакетах. Встроенные переводы есть только в
  необязательном делегате (decision 6), и только английский с русским.
- Встроенный снэкбар/тост подтверждения копирования.
- Выравнивание английских формулировок между скинами — это отдельное визуальное изменение.
- Подписи, которые рисует сам Flutter: кнопка «назад» `CupertinoNavigationBar` берётся из
  `CupertinoLocalizations` приложения, тултипы `TextField`/`TextBox` — из `MaterialLocalizations`/
  `FluentLocalizations`. Их локализует приложение подключением делегатов, как и всё остальное во Flutter.
- Ключи значений в детальном виде (`user_id`, `duration_ms`) — это данные, не подписи. Так же — имена
  уровней в строке и бейдже (`INFO`, `INF` у Fluent): это идентификаторы `LogLevel`, их не переводят, как
  роли в admin-клиенте.

## Decisions

### 1. Класс подписей как основной механизм, делегат — поверх него

`LogViewerLabels` — обычный `@immutable` класс с `const`-конструктором, который приложение заполняет из своих
ARB. Делегат локализации потребовал бы от пакета решать, какие языки поддерживать, тянуть
`flutter_localizations`, и всё равно не дал бы приложению поменять одну формулировку. Класс встраивается в
любой механизм локализации приложения (`gen-l10n`, `easy_localization`, константы), не навязывая ни один.
Готовые переводы — необязательный делегат, который сам лишь отдаёт `LogViewerLabels` (decision 6): класс
остаётся единственным, что читают скины.

### 2. Класс живёт в `structured_log_flutter`, а не в каждом скине

Так приложение, переключающее скин по платформе (Material на Android, Cupertino на iOS), заполняет подписи
один раз. Тот же приём, что с `logLevelColor()`: общее — в headless-ядре. Ядро при этом не узнаёт ни одной
дизайн-системы — в классе только строки и функция от `LogLevel`.

### 3. Все поля nullable, `null` = подпись скина по умолчанию

Альтернатива — ненулевые поля с одним английским значением по умолчанию. Она заставила бы либо поменять
видимые тексты двух скинов из трёх (таблица выше), либо завести три класса подписей. Nullable-поля сохраняют
каждому скину его формулировки, а приложение задаёт только то, что ему нужно. Цена — дефолты разбросаны по
скинам, и `LogViewerLabels` сам по себе не говорит, что будет показано. Это закрывается dartdoc каждого поля
(«Material: …, Fluent: …, Cupertino: …») и тестом каждого скина «без `labels` тексты прежние».

Подписи уровней фильтра — функция `String Function(LogLevel? minLevel)? levelFilterLabel` (`null` аргумент —
«все уровни»), а не пять полей: набор уровней в фильтре принадлежит скину, и при его расширении API не
разрастается. Поле функционального типа не мешает `const`-конструктору: передаётся tear-off.

Набор полей: `searchHint`, `pause`, `resume`, `clear`, `levelFilterLabel`, `allCategories`, `pageTitle`,
`emptyTitle`, `emptyMessage`, `noMatchesTitle`, `noMatchesMessage`, `clearFilters`, `contextHeading`, `copyContext`, `close`,
`backToList`. Поле, которое скин не показывает (`close` у Fluent/Cupertino, `backToList` у Material/Cupertino),
им просто не читается; так один объект годится для всех трёх. У Cupertino кнопки паузы и очистки —
иконки без текста и без подписи для экранного диктора; `pause`/`resume`/`clear` становятся их
`Semantics`-подписями (дефолт — `Pause`/`Resume`/`Clear all`, как тултипы двух других скинов), так что
VoiceOver озвучивает их и на языке приложения. `copyWith` есть — чтобы взять общий набор
приложения и поменять одну подпись под конкретный экран.

### 4. Передача — параметром конструктора, без `InheritedWidget`

`labels` принимают `*LogViewer`, `*LogViewerPage` и публичные составные виджеты (пустое состояние, панели и
шторка деталей, фильтр категорий); верхний виджет передаёт объект вниз явно. `InheritedWidget`-скоуп
отвергнут для первой версии: детальный вид Cupertino пушится новым маршрутом, а Material — модальной шторкой,
оба над `Navigator`, и скоуп внутри виджета до них не дотянется — пришлось бы всё равно передавать явно или
требовать скоуп над `MaterialApp`. Если понадобится «задать один раз на всё приложение», скоуп можно
добавить позже поверх параметра, не ломая его.

Существующий `allLabel` у `LogCategoryChips`/`LogCategoryComboBox`/`LogCategoryFilterBar` остаётся.
Порядок: явно переданный `allLabel` → `labels.allCategories` → прежний дефолт скина. Чтобы отличить
«передан» от «по умолчанию», дефолт `allLabel` становится `null` внутри (тип `String?`); для вызывающих,
передающих строку, ничего не меняется.

### 5. `onContextCopied` вызывается только после успешной записи

Сигнатура — `void Function(Map<String, dynamic> entry)?`: запись нужна приложению, если подтверждение зависит
от неё (или для аналитики), а текст оно может собрать само. Колбэк зовётся после завершения
`Clipboard.setData` и только если виджет, начавший копирование, ещё смонтирован. Если `setData` бросил,
колбэк не вызывается, а ошибка уходит в `FlutterError.reportError` вместо необработанной ошибки `Future` —
«скопировано» при неудаче было бы ложью. Отдельного `onCopyFailed` нет: потребителя у него пока нет.

Встроенного подтверждения нет (решение пользователя 19.10.2026): Material-шторка модальная, и снэкбар
корневого `Scaffold` оказался бы под её затемнением; у Fluent и Cupertino снэкбара нет вовсе, а у каждой
системы своё «правильное» подтверждение. Как показать — решает приложение.

### 6. `LogViewerLocalizations.delegate` — необязательные готовые en/ru

Добавлено по ходу реализации, решением пользователя: приложению на `flutter_localizations` (как Electro)
иначе пришлось бы руками собирать `LogViewerLabels` из своих ARB.

- **Без `flutter_localizations`, `intl` и `gen-l10n`.** `LocalizationsDelegate`/`Localizations` — часть
  `package:flutter/widgets.dart`; делегат пишется руками и грузит синхронно (`SynchronousFuture`). Строки —
  две константы `LogViewerLabels` в Dart, ARB нет. Поэтому довод о конфликте версий `intl` к делегату не
  относится, и `structured_log_flutter` остаётся без новых зависимостей.
- **`LogViewerLocalizations` несёт только `labels`.** Английский — `const LogViewerLabels()`: все поля `null`,
  то есть прежние формулировки каждого скина. Русский — полный набор, **один на все скины** (различия
  английских формулировок между скинами — наследие, переводить их тремя вариантами незачем); формулировки
  взяты из прототипа Electro (#188). Уровни в фильтре — «Все» и `Debug+` … `Error+` (имена уровней —
  идентификаторы, см. Non-Goals). `isSupported` — по `languageCode` `en`/`ru`; для прочих языков делегат не
  грузится, и действует то, что было бы без него.
- **Порядок разрешения поля:** явный параметр `labels` виджета → `LogViewerLocalizations` из контекста (если
  делегат зарегистрирован) → дефолт скина. Поле за полем, а не объект целиком: приложение берёт русский из
  делегата и меняет одну фразу через `labels`. Разрешение — одна функция ядра
  `LogViewerLocalizations.resolve(context, labels)`; её зовёт каждый публичный виджет скина, рисующий подписи
  (повторное разрешение идемпотентно, поэтому составным виджетам, используемым отдельно, тоже хватает её).
- **Это не противоречит decision 4.** `Localizations` стоит над `Navigator` приложения, поэтому и шторка
  Material, и пушнутый экран деталей Cupertino его видят; скоуп внутри виджета — не видели бы.
- Регистрация: `localizationsDelegates: [LogViewerLocalizations.delegate, ...]` в `MaterialApp`/
  `CupertinoApp`/`FluentApp`. Забытая регистрация даёт английский — тот же риск, что у любого делегата
  Flutter, и он касается только тех, кто выбрал этот путь.

## Risks / Trade-offs

- [Дефолты разбросаны по скинам] → dartdoc полей с дефолтом каждого скина; тест «без `labels` тексты
  прежние» в каждом скине.
- [Поле добавят в скин, но забудут в `LogViewerLabels`] → тест каждого скина, который задаёт **все** поля
  маркерами и проверяет, что на экране не осталось ни одного английского дефолта.
- [Ширина: русские подписи длиннее английских] → фильтр уровней Cupertino — `CupertinoSlidingSegmentedControl`,
  пять сегментов на узком экране. Тест на узкой ширине с длинными подписями проверяет отсутствие переполнения;
  если переполнение есть — правка раскладки в рамках этой заявки. **При реализации нашлось в четырёх местах, все
  исправлены:** строка кнопок шторки Material — теперь `Wrap`; шапка детального вида всех трёх скинов (панель
  Material у порога 700, панель Fluent в узкой раскладке, экран деталей Cupertino) — строка «уровень + время»
  стала `Wrap`, кнопка копирования — `Flexible` с многоточием. Сегментированный контрол Cupertino в
  горизонтальной прокрутке и не переполняется. Каждое место стережёт тест на русской локали на ширине 360/700.
- [`onContextCopied` после `pop` шторки] → колбэк не зовётся, если виджет размонтирован; это осознанно —
  иначе приложение показало бы подтверждение для экрана, которого нет.

## Migration Plan

Изменение аддитивное. Релиз: `structured_log_flutter` первым, затем три скина с поднятой нижней границей на
него (`melos version`/`melos publish` по уровням, как раньше). Откат — не обновлять зависимость; старый код
приложения с новыми версиями собирается без правок.

- [Русский набор делегата расходится с тем, что хочет приложение] → приложение перекрывает отдельные поля
  через `labels`, порядок разрешения это гарантирует (тест в каждом скине).
