## MODIFIED Requirements

### Requirement: Фильтр по произвольному полю контекста
Сервер SHALL поддерживать параметр `context.<key>` на `GET /v1/logs` и `GET /v1/logs/stream`, сравнивающий значение поля контекста записи с заданным. Ключ с точками SHALL адресовать вложенный объект.

Ключ, содержащий пустой сегмент — пустой ключ, ведущая точка, две точки подряд или завершающая точка, — SHALL отклоняться как `400 invalid_request` с `details.field`, называющим параметр целиком. Прочие ключи SHALL приниматься: ограничение существует затем, чтобы запрос не заканчивался ошибкой сервера или молча изменённым смыслом, а не затем, чтобы диктовать имена полей.

#### Scenario: Пустой сегмент отклоняется, а не роняет запрос
- **WHEN** приходит запрос с `context.=x`, `context..=x` или `context..a=x`
- **THEN** ответ `400 invalid_request` с `details.field`, называющим параметр; запрос не доходит до хранилища

#### Scenario: Обычный ключ работает как прежде
- **WHEN** приходит запрос с `context.user_id=42`
- **THEN** фильтр применяется, и ответ — обычная страница записей

#### Scenario: Необычный, но допустимый ключ не отвергается
- **WHEN** ключ содержит пробел, кавычку, скобку или не-ASCII
- **THEN** запрос обрабатывается — такие ключи читаются хранилищем без ошибки, и отказ отнял бы работающую возможность

#### Scenario: Завершающая точка отклоняется на обоих backend'ах
- **WHEN** приходит запрос с `context.a.=x`
- **THEN** ответ `400 invalid_request` с `details.field`, называющим параметр

Правило изначально измерялось по SQLite, который читает `$.a.` как `$.a`, и завершающая точка была разрешена. На PostgreSQL ключ не превращается в строку пути: он разбивается на элементы массива (`log_filter.dart`), и `a.` даёт `{a,}` — `22P02: malformed array literal`, то есть `500` с телом `Internal Server Error` вместо конверта (найдено прогоном против стенда 24.09.2026). Отклонение на обоих backend'ах выбрано вместо того, чтобы обрезать точку молча: эндпоинт должен отвечать одинаково, а не читать ключ, которого никто не писал.
