# Документация

*Read in [English](README.md).*

**Проект можно использовать двумя способами.** `structured_log` — и,
по желанию, просмотрщик логов внутри приложения — работает сам по
себе, без всякого сервера: см. [Руководство по
внедрению](guides/embedding-guide.ru.md). Self-hosted, мультитенантный
`structured_log_server` добавляйте, только когда нужно собирать логи
централизованно, искать по ним и делиться ими внутри команды; вместе с
ним идут `structured_log_remote_sync` (клиентский отправитель) и
`structured_log_admin_client` (веб-интерфейс). Дизайн именно этой
системы описывает остальная часть каталога.

**Здесь собраны документы двух видов — для двух разных читателей.**
[guides/](guides/) — продуктовая документация по задачам: по одному
руководству на каждую аудиторию, от самостоятельного внедрения пакетов
до эксплуатации, расширения self-hosted системы и вклада в неё. Всё
остальное здесь — `architecture/`, `operations/`, `api/` — справочная
документация: как система устроена и почему, для того, кто хочет
понять её дизайн, а не просто эксплуатировать её или интегрироваться с
ней. Если оба вида описывают один и тот же факт (форму
эндпоинта, флаг конфигурации), расходиться они не должны.

## Содержание

- [guides/](guides/) — пять руководств, сгруппированных по тому, как вы
  пользуетесь проектом: [руководство по
  внедрению](guides/embedding-guide.ru.md) (самостоятельно, без
  сервера); [руководство пользователя](guides/user-guide.ru.md),
  [руководство администратора/DevOps](guides/admin-guide.ru.md) и
  [руководство разработчика](guides/developer-guide.ru.md) (вместе с
  self-hosted сервером); и [руководство
  контрибьютора](guides/contributor-guide.ru.md) (вклад в этот
  репозиторий).
- [architecture/README.md](architecture/README.ru.md) — компоненты, поток
  запроса и принципы, повторяющиеся во всём дизайне.
- [architecture/data-model.md](architecture/data-model.ru.md) —
  мультитенантная модель сущностей (`User`/`Group`/`Team`/`Project`/...)
  и её схема хранения.
- [architecture/auth.md](architecture/auth.ru.md) — OAuth2/OIDC-подобный
  контракт токенов, `IdentityProvider`, отзыв прав через `token_version`
  и ограничитель частоты auth-эндпоинтов (throttling, без блокировки
  учётной записи).
- [architecture/rbac-and-lifecycle.md](architecture/rbac-and-lifecycle.ru.md)
  — роли и области видимости, блокировка и удаление аккаунтов (включая
  защиту основного администратора).
- [architecture/live-streaming.md](architecture/live-streaming.ru.md) —
  как устроена трансляция логов в реальном времени по SSE
  (`GET /v1/logs/stream`).
- [architecture/quotas-and-audit.md](architecture/quotas-and-audit.ru.md) —
  квоты на объём хранения для каждого проекта, административный аудит-лог,
  события аутентификации, которые пишутся рядом с ним, и сроки хранения
  тех и других.
- [architecture/admin-client.md](architecture/admin-client.ru.md) —
  собственная архитектура Flutter-приложения
  `structured_log_admin_client`.
- [architecture/technology-stack.md](architecture/technology-stack.ru.md) —
  почему выбрана каждая значимая зависимость и какой альтернативе её
  предпочли.
- [operations/configuration.md](operations/configuration.ru.md) — все
  настройки запуска: флаги, переменные окружения, приоритет источников,
  обращение с секретами и то, из-за чего сервер отказывается стартовать.
- [api/http-api.md](api/http-api.ru.md) — каждый HTTP-эндпоинт: параметры,
  тела запроса/ответа, специфичные для него ошибки и пример `curl`.
- [api/models.md](api/models.ru.md) — формы JSON-объектов, на которые
  ссылается `http-api.md` (`User`, `Project`, `LogEntry`, ответ токена, ...).
- [api/errors.md](api/errors.ru.md) — полный каталог ошибок: каждая пара
  HTTP-статус/код, которую может вернуть сервер, и где именно.

## Для кого это

**[guides/](guides/):**

- Тот, кому нужен `structured_log` — и, по желанию, просмотрщик логов
  внутри приложения — в собственном приложении, вовсе без сервера.
- Тот, кто вошёл в admin-клиент, разворачивает сервер или пишет код,
  работающий с self-hosted системой.
- Тот, кто пишет код в этом репозитории, в любом пакете.

См. [guides/README.ru.md](guides/README.ru.md), чтобы выбрать нужное
руководство.

**`architecture/`, `operations/`, `api/`:**

- Тот, кому нужно обоснование дизайн-решения, а не только его
  результат — как части системы связаны между собой и почему они
  устроены именно так.
- Ревьюеры, проверяющие соответствие реализации задуманному дизайну.
