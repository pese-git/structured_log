## A Melos + FVM monorepo

Nine packages, grouped by role: libraries you embed in your own app, a
self-hosted server, and the standalone admin client that operates it.

<CardGrid stagger>
	<Card title="structured_log" icon="seti:dart">
		The core library — structured JSON logging with context binding, typed
		correlation fields, processors, and multi-sink output routing. Zero
		runtime dependencies beyond `meta`. [Published on
		pub.dev](https://pub.dev/packages/structured_log).
	</Card>
	<Card title="structured_log_flutter" icon="seti:flow">
		A headless log-viewer core for Flutter: a bounded `LogBuffer` that plugs
		into `structured_log` as a sink, and a filterable `LogViewerController`.
		No design-system dependency. [Published on
		pub.dev](https://pub.dev/packages/structured_log_flutter).
	</Card>
	<Card title="structured_log_material / _fluent / _cupertino" icon="puzzle">
		Three ready-to-use in-app log viewers built on `structured_log_flutter`
		— Material 3, Fluent UI (WinUI-style), and Cupertino (iOS-style) — each
		with search, level/category filtering, and a runnable example app.
		Published on pub.dev.
	</Card>
	<Card title="structured_log_http" icon="rocket">
		An `HttpLogOutput` sink that ships entries to a `structured_log_server`
		instance over HTTP: batching, retry with backoff, a bounded buffer, and
		`flushed` to await delivery before exit. Not yet published.
	</Card>
	<Card title="structured_log_server" icon="setting">
		A self-hosted, multi-tenant server for ingestion, storage, query and
		live streaming (SQLite or PostgreSQL) — groups, projects, teams, secret
		keys, RBAC, quotas, retention, and an audit log.
	</Card>
	<Card title="structured_log_admin_client" icon="laptop">
		The web app operators and their teams use: sign-in, a role-scoped
		dashboard, resource management, log search with live tailing, user
		management, and the audit log. Localized English/Russian.
	</Card>
</CardGrid>
