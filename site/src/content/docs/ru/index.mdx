## Monorepo на Melos + FVM

Девять пакетов, сгруппированных по роли: библиотеки, встраиваемые в
приложение, self-hosted сервер и самостоятельный admin-клиент, который им
управляет.

<CardGrid stagger>
	<Card title="structured_log" icon="seti:dart">
		Базовая библиотека — структурированный JSON-лог с привязкой контекста,
		типизированными correlation-полями, процессорами и маршрутизацией по
		нескольким выходам. Без сторонних runtime-зависимостей, кроме `meta`.
		[Опубликован на pub.dev](https://pub.dev/packages/structured_log).
	</Card>
	<Card title="structured_log_flutter" icon="seti:flow">
		Headless-ядро просмотра логов для Flutter: ограниченный `LogBuffer`,
		подключаемый к `structured_log` как sink, и фильтрующий
		`LogViewerController`. Не зависит ни от одной дизайн-системы.
		[Опубликован на
		pub.dev](https://pub.dev/packages/structured_log_flutter).
	</Card>
	<Card title="structured_log_material / _fluent / _cupertino" icon="puzzle">
		Три готовых к использованию просмотрщика логов поверх
		`structured_log_flutter` — Material 3, Fluent UI (в стиле WinUI) и
		Cupertino (в стиле iOS) — каждый с поиском, фильтрацией по
		уровню/категории и рабочим примером. Опубликованы на pub.dev.
	</Card>
	<Card title="structured_log_http" icon="rocket">
		Sink `HttpLogOutput`, отправляющий записи на экземпляр
		`structured_log_server` по HTTP: батчинг, retry с backoff,
		ограниченный буфер и `flushed` для ожидания доставки перед выходом.
		Пока не опубликован.
	</Card>
	<Card title="structured_log_server" icon="setting">
		Self-hosted, multi-tenant сервер приёма, хранения, поиска и живой
		трансляции логов (SQLite или PostgreSQL) — группы, проекты, команды,
		секретные ключи, RBAC, квоты, retention и аудит-лог.
	</Card>
	<Card title="structured_log_admin_client" icon="laptop">
		Веб-приложение, которым пользуются операторы и их команды: вход,
		ролевой дашборд, управление ресурсами, поиск логов с живой лентой,
		управление пользователями и аудит-лог. Локализовано на английский и
		русский.
	</Card>
</CardGrid>
