Базовая библиотека, экосистема in-app просмотра логов и, по желанию,
self-hosted сервер. Всё ниже работает полностью самостоятельно, вовсе
без сервера; добавляйте `structured_log_server`, только когда нужно
собирать эти логи централизованно, искать по ним и делиться ими внутри
команды.

## Быстрый старт

<Tabs>
<TabItem label="Самостоятельно, без сервера">

<Steps>

1. **Добавьте `structured_log`.**

   ```yaml
   dependencies:
     structured_log: ^0.2.0
   ```

2. **Логируйте.**

   ```dart
   import 'package:structured_log/structured_log.dart';

   void main() {
     getLogger().info('user_login', context: {'user_id': 42});
   }
   ```

3. **По желанию — смотрите логи вживую внутри своего Flutter-приложения**
   — headless-ядро плюс готовый скин Material/Fluent/Cupertino,
   полностью локально, без сети (полный разбор:
   [Руководство по внедрению](/ru/guides/embedding-guide/)).

</Steps>

</TabItem>
<TabItem label="Вместе с self-hosted сервером">

<Steps>

1. **Запустите сервер.** Поднимает `structured_log_server` и
   admin-клиент за одним nginx — больше ничего устанавливать не нужно.

   ```bash
   cd deploy && cp .env.example .env && ./deploy.sh
   ```

   Откройте `http://localhost:8080` и войдите с временным паролем,
   напечатанным в стартовом логе сервера (подробности:
   [Руководство администратора](/ru/guides/admin-guide/)).

2. **Создайте проект и секретный ключ.** В admin-клиенте: группа,
   проект внутри неё, затем секретный ключ для этого проекта — он
   показывается один раз, при создании (пошагово со скриншотами:
   [Руководство пользователя](/ru/guides/user-guide/)).

3. **Отправьте логи из своего приложения.**

   ```dart
   import 'package:structured_log/structured_log.dart';
   import 'package:structured_log_http/structured_log_http.dart';

   void main() {
     StructlogConfiguration.configure(sinks: [
       LogSink(name: 'server', output: HttpLogOutput(
         serverUrl: 'https://logs.example.com',
         projectSecretKey: 'slk_...', // из шага 2
       )),
     ]);

     getLogger().info('user_login', context: {'user_id': 42});
   }
   ```

   Записи появляются в живой ленте admin-клиента сразу же — без
   перезапуска, без опроса (подробности:
   [Руководство разработчика](/ru/guides/developer-guide/)).

</Steps>

</TabItem>
</Tabs>

## Два способа пользоваться

### Самостоятельно — сети не касаются вовсе

<CardGrid stagger>
	<Card title="structured_log" icon="seti:dart">
		Структурированное JSON-логирование для Dart — привязка контекста,
		correlation-поля, процессоры, маршрутизация по нескольким выходам.
		Без сторонних зависимостей, кроме `meta`.
		[Использование и API](/ru/packages/structured_log/) ·
		[pub.dev](https://pub.dev/packages/structured_log).
	</Card>
	<Card title="structured_log_flutter" icon="seti:flow">
		Headless-ядро просмотра логов для Flutter — `LogBuffer`-sink и
		фильтрующий `LogViewerController`, без привязки к дизайн-системе.
		[Использование и API](/ru/packages/structured_log_flutter/) ·
		[pub.dev](https://pub.dev/packages/structured_log_flutter).
	</Card>
	<Card title="structured_log_material, structured_log_fluent, structured_log_cupertino" icon="puzzle">
		Три готовых к использованию просмотрщика логов поверх него —
		[Material 3](/ru/packages/structured_log_material/),
		[Fluent UI](/ru/packages/structured_log_fluent/) и
		[Cupertino](/ru/packages/structured_log_cupertino/) — у каждого
		поиск и фильтрация из коробки. Опубликованы на pub.dev.
	</Card>
</CardGrid>

### Self-hosted сервис — подключайте, когда понадобится

<CardGrid stagger>
	<Card title="structured_log_http" icon="rocket">
		Отправляет записи на `structured_log_server` по HTTP — батчинг,
		retry с backoff, ограниченный буфер. Использован в быстром старте
		выше. [Использование и API](/ru/packages/structured_log_http/).
		Пока не опубликован.
	</Card>
	<Card title="structured_log_server" icon="setting">
		Self-hosted, multi-tenant сервер — принимает и хранит логи ваших
		приложений, позволяет искать их и следить за ними в реальном
		времени. SQLite или PostgreSQL.
	</Card>
	<Card title="structured_log_admin_client" icon="laptop">
		Веб-приложение для повседневной работы операторов — дашборд,
		управление ресурсами, живой поиск логов, управление
		пользователями, аудит-лог.
	</Card>
</CardGrid>
